# Data and artifact dictionary

All physical observations in this study are generated by the included numerical simulators. External datasets and pretrained weights are not required.

| Artifact | Meaning |
|---|---|
| `experiments/*/configs/*.json` | Fixed run profiles, training budgets, seeds, grids, and statistical settings |
| `results/*/protocol.json` | Frozen configuration, source fingerprint, and local protocol metadata |
| `results/development/runs/*/record.json` | One of the 864 development candidate records |
| `results/confirmation/resolution/g*/runs/*/record.json` | One of the 288 resolution-stage candidate records |
| `results/confirmation/selector/g64/runs/*/record.json` | One of the 432 new-selector candidate records |
| `runs/*/evaluation.npz` | Compressed NumPy per-trajectory evaluation arrays; includes evidence used by the report code |
| `bank.json` | Consolidated candidate metadata; duplicates information for analysis convenience |
| `banks/*.json` | Perturbation-bank diagnostics and generation metadata |
| `data/*.json` | Generated-data metadata and provenance; not the training trajectory arrays themselves |
| `selection_inputs.json` | Allowed information supplied to selection before test evaluation |
| `selection_manifest.json` | Frozen choices and selection provenance |
| `evaluation_plan.json` | Locked evaluation choices and hashes |
| `numerical_audit.json` | Numerical checks defined by the corresponding source version |
| `reports/report.json` | Structured report with effects, uncertainty, status, costs, and caveats |
| `reports/report.md` | Human-readable report written by the original runner |
| `experiments/confirmation/development/validation_bank.json` | Filtered development rows used to fit the new selector |
| `experiments/confirmation/development/provenance.json` | Allowed fields and hashes linking that bank to development results |
| `manifest.json` | Packaging integrity inventory; not a preregistration |

`family` identifies an equation, `kind` an architecture, `prior` a physical-operator setting, `seed` a training replicate, and `arm` an augmentation choice. A `task_id` groups the alternative arms for a fixed equation/architecture/prior/seed. A `run_id` includes its arm. The resolution stage also distinguishes the grid in its directory and protocol.

The source routines defining evaluation-array keys and metrics are `experiments/development/lpb/engine.py`, `experiments/development/lpb/reporting.py`, and `experiments/confirmation/lpb/confirmation_report.py`. Preserve the original schema when replaying reports. No object-pickle loading is needed to inspect NPZ arrays.

The archived source and report text retain historical RunPod paths. Those strings document the run environment; reproduction uses the relative paths in this repository's guide. Checkpoints, optimizer states, generated training caches, and augmentation-bank array caches were excluded from the original sharing archives. Fresh runs regenerate them. A saved evaluation array is sufficient for report replay but cannot be used to resume model training.
